# 관리자 화면 PRD (프런트엔드 UI)

## 1. 개요

### 1.1 목적
관리자가 주문 현황을 한눈에 파악하고, 재고를 조정하며, 들어온 주문을 접수·처리할 수 있는 관리자 화면의 UI/UX 요구사항을 정의한다.

### 1.2 대상 사용자
주문 및 재고를 관리하는 운영자(관리자)

### 1.3 관련 문서
- [커피 주문 앱 PRD](./PRD.md) — 프로젝트 전반 개요 및 기술 스택
- [주문하기 화면 PRD](./PRD-주문하기-화면.md) — 고객 주문 화면

## 2. 화면 구성 (와이어프레임 기준)

### 2.1 화면 개요
- **화면명:** 관리자
- **경로:** `/admin` (라우팅 정책에 따름)
- **역할:** 주문 통계 조회, 재고 관리, 주문 상태 관리(접수·제조 중·제조 완료)
- **레이아웃:** 상단 헤더 → 관리자 대시보드 → 재고 현황 → 주문 현황 (세로 배치)

### 2.2 헤더 영역
| 요소 | 설명 |
|------|------|
| **로고/브랜드** | 좌측 상단에 "COZY" 표시 (주문하기 화면과 동일) |
| **탭 네비게이션** | 우측 상단: "주문하기", "관리자"(선택 상태) — 탭 클릭 시 해당 화면으로 이동 |

### 2.3 관리자 대시보드 영역
- **섹션 제목:** "관리자 대시보드"
- **표시 항목:** 주문 상태별 건수를 요약하여 표시
  - **총 주문:** 전체 주문 수 (예: 총 주문 1)
  - **주문 접수:** 접수된 주문 수 (예: 주문 접수 1)
  - **제조 중:** 제조 진행 중인 주문 수 (예: 제조 중 0)
  - **제조 완료:** 제조 완료된 주문 수 (예: 제조 완료 0)
- 운영 상황을 한눈에 파악할 수 있도록 숫자 중심으로 구성한다.

### 2.4 재고 현황 영역
- **섹션 제목:** "재고 현황"
- **표시 형식:** 메뉴별로 한 행씩, 다음 정보 표시
  - **메뉴명:** 예) 아메리카노(ICE), 아메리카노(HOT), 카페라떼(HOT)
  - **현재 재고:** "N개" 형태 (예: 10개)
  - **조절 버튼:** "+" 버튼(재고 증가), "-" 버튼(재고 감소)
- 버튼 클릭 시 해당 메뉴의 재고 수량이 즉시 반영되도록 한다(서버 연동 또는 로컬 상태 반영).

### 2.5 주문 현황 영역
- **섹션 제목:** "주문 현황"
- **표시 형식:** 주문 단위로 한 행(또는 카드)씩 표시
  - **주문 일시:** 예) 7월 31일 13:00
  - **주문 내용:** 메뉴명 + 수량 (예: 아메리카노(ICE) X 1)
  - **금액:** 예) 4,500원
  - **액션 버튼:** "주문 접수" — 클릭 시 해당 주문을 접수 상태로 변경
- 대기 중인 주문만 목록에 노출하거나, 상태별 필터를 둘 수 있다(구현 시 결정).
- 접수 후에는 "제조 중" 등 다음 단계로 진행할 수 있는 버튼/플로우를 고려할 수 있다.

## 3. 기능 요구사항

### 3.1 관리자 대시보드
- **통계 표시:** 총 주문, 주문 접수, 제조 중, 제조 완료 건수를 서버(또는 로컬 데이터) 기준으로 표시한다.
- **갱신:** 화면 진입 시 또는 주기/수동 갱신으로 최신 수치를 반영한다.

### 3.2 재고 현황
- **목록:** 메뉴(상품)별 현재 재고 수량을 목록으로 표시한다.
- **증가/감소:** "+" 클릭 시 재고 1 증가, "-" 클릭 시 재고 1 감소. 변경 시 서버 API 호출 또는 로컬 상태 업데이트.
- **제한(선택):** 재고가 0일 때 "-" 비활성화, 최대 재고 상한 적용 여부는 정책에 따라 결정.

### 3.3 주문 현황
- **목록 표시:** 접수 대기 중인 주문(및 필요 시 다른 상태 주문)을 일시·메뉴·수량·금액과 함께 표시한다.
- **주문 접수:** "주문 접수" 버튼 클릭 시 해당 주문을 "주문 접수" 상태로 변경하고, 대시보드 수치를 갱신한다.
- **(확장)** 접수 후 "제조 중" → "제조 완료" 등 단계별 상태 변경 버튼을 추가할 수 있다.

### 3.4 네비게이션
- 헤더의 **"주문하기"** 탭 클릭 시 주문하기 화면으로 이동한다.
- **"관리자"** 탭은 현재 화면이므로 선택(활성) 상태로 표시한다.

### 3.5 기타
- 사용자 인증은 범위 외이므로, 관리자 화면 접근 제어는 추후 요구사항에 따라 정의한다.

## 4. 비기능 요구사항

### 4.1 기술
- **프런트엔드:** HTML, CSS, React, JavaScript (기존 PRD 기준)
- **데이터:** 대시보드 통계·재고·주문 목록은 백엔드 API를 통해 조회·갱신한다.

### 4.2 UX
- 대시보드 숫자와 재고/주문 목록이 한 화면에서 읽기 쉽게 배치된다.
- "+" / "-" 및 "주문 접수" 버튼은 터치·클릭이 명확하도록 한다.

### 4.3 접근성 (선택)
- 버튼과 링크에 적절한 라벨을 제공하는 것을 권장한다.
