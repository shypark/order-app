# 주문하기 화면 PRD (프런트엔드 UI)

## 1. 개요

### 1.1 목적
고객이 커피 메뉴를 탐색하고 장바구니에 담은 뒤 주문을 완료할 수 있는 주문하기 화면의 UI/UX 요구사항을 정의한다.

### 1.2 대상 사용자
앱을 이용하여 커피를 주문하는 일반 고객

### 1.3 관련 문서
- [커피 주문 앱 PRD](./PRD.md) — 프로젝트 전반 개요 및 기술 스택

## 2. 화면 구성 (와이어프레임 기준)

### 2.1 화면 개요
- **화면명:** 주문하기
- **경로:** `/` 또는 `/order` (라우팅 정책에 따름)
- **역할:** 메뉴 조회, 옵션 선택, 장바구니 담기, 주문 요청
- **레이아웃:** 상단 헤더 → 메뉴 카드 영역(가로 배치) → 하단 장바구니 영역

### 2.2 헤더 영역
| 요소 | 설명 |
|------|------|
| **로고/브랜드** | 좌측 상단에 "COZY" 표시 |
| **탭 네비게이션** | 우측 상단: "주문하기"(선택 상태), "관리자" — 탭 클릭 시 해당 화면으로 이동 |

### 2.3 메뉴(상품) 표시 영역
- 메뉴 항목을 **카드 형태**로 가로 배치(예: 3열 그리드).
- 각 카드 구성:
  - **이미지 영역:** 상품 이미지 (플레이스홀더 지원)
  - **메뉴명:** 예) 아메리카노(ICE), 아메리카노(HOT), 카페라떼(HOT)
  - **가격:** 원화 표기 (예: 4,500원, 4,000원)
  - **간단한 설명:** "간단한 설명..." 형태의 짧은 설명 텍스트
  - **옵션 (체크박스):**
    - "샷 추가(+500원)"
    - "시럽 추가(+0원)"
  - **담기 버튼:** 카드 하단 "담기" — 클릭 시 선택한 옵션과 함께 장바구니에 추가

### 2.4 장바구니 영역
- **섹션 제목:** "장바구니" (영역 좌측 상단)
- **장바구니 항목:** 각 행에 다음 정보 표시
  - 메뉴명 + 선택 옵션 (예: "아메리카노(ICE) (샷 추가)")
  - 수량 (예: "X 1", "X 2")
  - 해당 항목 금액 (예: 4,500원, 8,000원)
- **총 금액:** 우측에 "총 금액 12,500원" 형태로 강조 표시
- **주문하기 버튼:** 총 금액 아래에 큰 "주문하기" 버튼 배치

## 3. 기능 요구사항

### 3.1 메뉴 표시
- 커피 메뉴를 **카드 형태**로 가로 배치하여 표시한다.
- 각 카드에 **메뉴명**, **가격**, **간단한 설명**, **상품 이미지(또는 플레이스홀더)** 를 노출한다.
- 메뉴별 **추가 옵션**을 체크박스로 제공한다.
  - 예: 샷 추가(+500원), 시럽 추가(+0원) — 옵션 선택 시 금액에 반영하여 담기 가능하도록 한다.

### 3.2 옵션 선택 및 담기
- 사용자가 **옵션(체크박스)** 을 선택한 뒤 **"담기"** 버튼을 누르면 해당 메뉴+옵션 조합이 장바구니에 추가된다.
- 동일한 "메뉴+옵션 조합"이 이미 장바구니에 있으면 수량을 증가시키거나, 별도 행으로 추가하는 정책 중 하나를 적용한다(구현 시 결정).
- 옵션 미선택 시 기본 메뉴만 담기며, 옵션 가격은 0원으로 처리한다.

### 3.3 장바구니
- **담기:** "담기" 클릭 시 선택한 메뉴와 옵션을 장바구니에 추가한다.
- **표시:** 각 항목에 "메뉴명 (선택 옵션)", 수량(X N), 항목별 금액을 표시한다. (예: "아메리카노(ICE) (샷 추가) X 1 4,500원")
- **수량 변경:** 이미 담긴 항목의 수량을 증가/감소할 수 있다(와이어프레임에 수량 조절 UI가 있다면 반영).
- **삭제:** 장바구니에서 항목을 개별 삭제할 수 있다.
- **총 금액:** 장바구니 내 금액 합계를 실시간으로 표시한다. ("총 금액 N원" 형태, 우측 정렬 등)
- 장바구니가 비어 있을 때는 **주문하기 버튼 비활성화** 또는 안내 문구 표시를 권장한다.

### 3.4 주문하기
- **주문하기** 버튼 클릭 시 장바구니 내용을 기반으로 주문 API를 호출한다.
- 주문 성공 시 장바구니를 비우고, 성공 메시지 또는 주문 번호 등을 사용자에게 표시한다.
- 주문 실패 시 에러 메시지를 표시하고, 필요 시 재시도 가능하도록 한다.

### 3.5 네비게이션
- 헤더의 **"관리자"** 탭 클릭 시 관리자 화면으로 이동한다.
- **"주문하기"** 탭은 현재 화면이므로 선택(활성) 상태로 표시한다.

### 3.6 기타
- 사용자 인증·결제는 범위 외이므로, 주문 요청만 처리한다.

## 4. 비기능 요구사항

### 4.1 기술
- **프런트엔드:** HTML, CSS, React, JavaScript (기존 PRD 기준)
- **상태:** 장바구니 상태는 클라이언트(React state/Context 등)에서 관리하며, 주문 시에만 서버로 전송

### 4.2 UX
- 메뉴와 장바구니 조작이 직관적이어야 한다.
- 버튼·터치 영역은 터치 디바이스에서도 사용하기 쉬운 크기를 유지한다.

### 4.3 접근성 (선택)
- 주요 버튼과 링크에 적절한 라벨 제공을 권장한다.
