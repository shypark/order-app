# 프론트엔드 개선 사항 (검토 요약)

## 이번에 반영한 내용

1. **메뉴 사진**
   - 각 메뉴 카드에 이미지 표시 (placeholder URL 사용, 실서비스에서는 `public/images` 또는 CDN 권장)
   - 이미지 로드 실패 시 "이미지" 플레이스홀더로 대체

2. **제조 완료 시 재고 차감**
   - 주문 데이터에 `menuId` 포함
   - 관리자에서 "제조 완료" 클릭 시 해당 주문의 메뉴별 수량만큼 재고에서 차감
   - 재고 관리 대상(아메리카노 ICE/HOT, 카페라떼 HOT)만 차감

---

## 추가로 고려할 개선 사항

### 1. 접근성
- **주문하기 버튼**: `aria-label="주문하기"` 등으로 보조 기기 지원 (현재는 텍스트로 의미 전달됨)
- **헤더 로고**: "COZY"를 홈으로 이동하는 링크로 두면 키보드/스크린리더 사용에 유리

### 2. 사용자 피드백
- 주문 접수/제조 완료 시 `alert` 대신 토스트 또는 인라인 메시지로 표시하면 UX 개선
- 장바구니 담기 시 짧은 피드백(예: "장바구니에 담았습니다") 고려

### 3. 재고와 주문 연동
- 재고가 0인 메뉴는 주문 화면에서 "품절" 표시 또는 담기 비활성화
- (현재는 재고와 주문하기 화면이 연동되지 않음 — 백엔드 연동 시 함께 설계 권장)

### 4. 데이터 유지
- 새로고침 시 주문·재고가 초기화됨 (Context만 사용)
- 백엔드 API 연동 후 서버에 저장하면 유지 가능

### 5. 에러 처리
- 이미지 로드 실패는 플레이스홀더로 처리 완료
- API 연동 시 네트워크 오류, 4xx/5xx 처리 및 재시도/메시지 표시 추가 권장

### 6. 성능
- 메뉴 이미지에 `loading="lazy"` 적용됨
- 필요 시 메뉴 목록 가상화(긴 목록) 또는 코드 스플리팅 검토

### 7. 테스트
- 주문하기 → 관리자에서 주문 접수 → 제조 시작 → 제조 완료 시 재고 감소 플로우 수동 확인 권장
- 재고 0일 때 재고 카드에서 "-" 버튼 비활성화 확인

## 테스트 체크리스트

- [ ] 주문하기에서 메뉴 선택 후 담기 → 장바구니 표시
- [ ] 주문하기 클릭 → 관리자 화면에서 해당 주문 표시
- [ ] 주문 접수 → 제조 시작 → 제조 완료 순서 동작
- [ ] 제조 완료 시 재고 현황에서 해당 메뉴 재고 감소
- [ ] 재고 0일 때 "-" 버튼 비활성화
- [ ] 주문하기/관리자 탭 전환
- [ ] 메뉴 이미지 표시 (네트워크 필요), 실패 시 플레이스홀더
